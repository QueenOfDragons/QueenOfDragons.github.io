From SAS to Python: why "translating" is not enough

Many companies are moving their SAS programs to Python, often by having them translated automatically, AI included. The resulting code is clean, runs without errors... and produces different numbers. No warning, no red message: the totals at the bottom of the report simply stop adding up.

It happens because SAS does many things "on its own", silently, and a line-by-line translation cannot see them. Here is an example. The program and the data are made up, but the behaviour of SAS and of pandas (the most widely used Python library for tables) is real.

The case: late payments at a bank

A bank has three tables: loan instalments (how much is due and when), the payments actually received, and a lookup table with the customer segment (RETAIL, SME, large corporate...). An instalment can be paid in several parts, or not at all. For each instalment we want the amount still due, the loan's maximum delay so far, the months past due of each instalment, and how many months in a row the customer has not paid. These are the building blocks for exposure, default and PD (probability of default).

Step 1: joining instalments and payments

SAS 
/* Reference date: end of previous month */
%let data_rif = %sysfunc(intnx(month, %sysfunc(today()), -1, E));
/* in this example: 31OCT2026 */

data work.rate_pag (keep=id_prestito n_rata data_scadenza
                         data_pagamento importo_pagato residuo);
  merge dwh.rate      (in=in_rata
                       where=(data_scadenza  <= &data_rif))
        dwh.pagamenti (where=(data_pagamento <= &data_rif));
  by id_prestito n_rata;
  if in_rata;
  /* running balance over partial payments */
  residuo = sum(residuo, -importo_pagato);
  format residuo commax12.2;
run;
Python, "machine" translation 
chiavi = ["id_prestito", "n_rata"]
df = rate.merge(pagamenti, how="left",
                on=chiavi)
df["importo_pagato"] = (
    df["importo_pagato"].fillna(0))
df["residuo"] = (df["residuo"]
                 - df["importo_pagato"])

Trap 1: a one-to-many MERGE "remembers"

The running balance here is intended, and it is an elegant way to get it in SAS. In a MERGE with BY, when an instalment has two payments, SAS reads the instalment row only once: on the second row the variables coming from RATE stay in the PDV (the DATA step's working area) with the value already modified on the row before. So residuo goes down by itself: 500 − 200 = 300, then 300 − 300 = 0.

A translator only sees a subtraction. A pandas merge copies the original value onto every row: 500 − 200 = 300, then 500 − 300 = 200. The instalment still looks unpaid although it was paid in full.

Python, faithful to SAS 
pagamenti = pagamenti.sort_values(chiavi, kind="stable")   # same order as the SAS BY
df = rate.merge(pagamenti, how="left", on=chiavi)
df["importo_pagato"] = df["importo_pagato"].fillna(0)
df["residuo"] = df["residuo"] - df.groupby(chiavi)["importo_pagato"].cumsum()

Step 2: the history of each loan

SAS 
/* DO loop: one DATA step iteration per loan */
data work.storia;
  if 0 then set dwh.segmenti(keep=id_prestito segmento);
  if _n_ = 1 then do;
    /* customer segment lookup, loaded once */
    /* the last one loaded wins */
    declare hash seg(dataset:'dwh.segmenti',
                     duplicate:'r');
    seg.defineKey('id_prestito');
    seg.defineData('segmento');
    seg.defineDone();
  end;
  do until (last.id_prestito);
    set work.rate_pag;
    by id_prestito n_rata;
    if first.id_prestito then do;
      /* failed find: the value is NOT reset */
      if seg.find() ne 0 then segmento = 'ND';
    end;
    if last.n_rata then do;
      giorni_rit  = intck('day', data_scadenza,
                          data_pagamento);
      rit_max     = max(rit_max, giorni_rit);
      mesi_rit    = intck('month', data_scadenza,
                    coalesce(data_pagamento, &data_rif));
      insoluta    = (residuo > 0.005);
      mesi_consec = ifn(insoluta, sum(mesi_consec, 1), 0);
      output;
    end;
  end;
  label rit_max     = 'Ritardo massimo (giorni)'
        mesi_rit    = 'Mesi di scaduto'
        mesi_consec = 'Mesi consecutivi di insoluto';
run;
Python, "machine" translation 
st = df.drop_duplicates(chiavi,
                        keep="last").copy()
st = st.merge(segmenti, how="left",
              on="id_prestito")
g = st["id_prestito"]
st["giorni_rit"] = (st["data_pagamento"]
                    - st["data_scadenza"]).dt.days
st["rit_max"] = (st.groupby(g)["giorni_rit"]
                 .cummax())
fine = st["data_pagamento"].fillna(data_rif)
st["mesi_rit"] = ((fine - st["data_scadenza"])
                  .dt.days // 30)
ins = st["residuo"] > 0.005
blocco = (~ins).groupby(g).cumsum()
st["mesi_consec"] = (ins.astype(int)
                     .groupby([g, blocco])
                     .cumsum())

Trap 2: the DO loop and missing values

In a DO loop the DATA step runs once per loan: computed variables go back to missing at the start of each loan with no RETAIN and no FIRST., and they accumulate inside the loop. The MAX function then ignores missing values: for an unpaid instalment the maximum delay stays what it was.

The pandas cummax leaves NaN (Python's missing value) on exactly that row, and if it is the loan's last row the maximum delay vanishes from the report. A row-by-row Python max() is even worse: max(nan, -1) returns nan, max(-1, nan) returns -1. The result depends on the order of the arguments.

Trap 3: INTCK does not count days

intck('month', ...) counts how many month boundaries are crossed, not how many "full" months have passed: from 31 August to 25 September it returns 1. That is exactly the logic of past-due buckets by reference month.

The most common translation, days divided by 30, gives 0. And with a payment one day early it gets worse: in Python -1 // 30 is -1, because integer division rounds down, while SAS gives 0. A negative number of months past due, with no error at all.

Trap 4: a lookup table with duplicate keys

The hash object loads SEGMENTI into memory once and, with duplicate:'r', keeps the last row per key: loan 1002 is SME. Watch the find() too: if the key is missing, the value stays the one of the previous loan, because variables read with SET are not reset. That is why the 'ND' branch is not a whim.

A pandas merge instead matches loan 1002 with both rows: its instalments double, from 3 to 6, and so does the exposure summed later on. No error, unless you ask pandas to check with validate.

Python, faithful to SAS (an excerpt) 
seg = segmenti.drop_duplicates("id_prestito", keep="last")        # the hash's duplicate:'r'
st = st.merge(seg, how="left", on="id_prestito", validate="many_to_one")
st["segmento"] = st["segmento"].fillna("ND")
st["rit_max"] = (st.groupby(g)["giorni_rit"].cummax()
                 .groupby(g).ffill())                  # SAS MAX: missing values do not count
st["mesi_rit"] = ((fine.dt.year  - st["data_scadenza"].dt.year) * 12
                  + (fine.dt.month - st["data_scadenza"].dt.month))   # INTCK 'month' counts month boundaries
